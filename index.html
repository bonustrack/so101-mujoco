How the loop works

Jev is a decision model, not a chat model: it picks from fixed lists, with a probability for each option. Jev decides what, code decides how. One Jev call reads the goal: the task (take one object, stack the boxes, stack everything, put one object on another, drive or turn, drive to an object), which object, onto which, the order, the spot, and which way and how far to drive. Code turns the task into a plan of steps, biggest box at the bottom, and plans again after every step, so a box that falls goes back on the list. Each step is a skill code runs and checks: drive, pick or place. Code solves the joint angles (IK) and MuJoCo moves the arm. The arm reaches about 10 cm up with its fingers pointing down, so a tower stops there.

The arm rides on a wheeled base: the left and right wheel pairs turn at set speeds, together to drive, against each other to turn on the spot. A drive follows a path planned on a map of the floor, around every object, up to 30 cm/s, and stops at the first touch to plan again. When an object or a tower is out of the arm's reach, the plan first drives up to it. Parked, the base is braked.

A step that fails is tried another way, each way once: the jaws turned 90°, another side, backing off first. When no way is left, one Jev call chooses: try once more, leave the object out, or stop. Every task has a time budget.

The key stays in this browser. Calls go through this site's Netlify Function, because TypeSafe blocks browser calls. It passes the key on and never stores or logs it.
